# MIMIC-IV-ECG Machine-Report Concordance Design

**Status:** design approved for implementation; the generic phrase parser,
metadata join auditor, aggregate PAC statement auditor, and synthetic tests are
implemented. No MIMIC-IV-ECG files have been downloaded, inspected, classified,
or scored for this project. The user approved exploring
v1.0 only for concordance with automated machine-report statements; this does
not approve any real phrase mapping or make machine reports clinical reference
labels.

## Permitted Question

If an authorized and sufficiently resourced copy becomes available, quantify
how frozen TITAN PAC outputs agree with PAC-related statements in the
automatically generated ECG machine report. Candidate systems are the frozen
V4.5 P8 PAC output and the prespecified V4.6 PAC heads if that SPH development
experiment is completed. This is a cross-source machine-report concordance
analysis, not diagnostic accuracy, clinical validation, or a replacement for
independent clinical adjudication.

The official MIMIC-IV-ECG v1.0 file description identifies `report_0` through
`report_17` as machine-generated report lines and explains that blank report
columns can occur between populated lines. The data dictionary describes each
`report_#` as a text-based cardiology report generated by the ECG machine. The
v1.0 page describes ECG waveforms, machine measurements, and links to
cardiologist reports; it does not provide the cardiologist free-text report
content in this release. See the [file description](https://physionet.org/content/mimic-iv-ecg/1.0/files/)
and [report data dictionary](https://physionet.org/content/mimic-iv-ecg/1.0/machine_measurements_data_dictionary.csv).

## Prespecified Analysis Requirements

1. Pin the PhysioNet version, license text, per-file SHA-256 values, retrieval
   date, and code commit. Preserve the source archive unchanged in restricted
   CEDIA storage.
2. Define the ECG unit by `study_id`, subject cluster by `subject_id`, and the
   join between the waveform record list and machine measurements before
   looking at performance. Reject duplicate keys, missing joins, and
   conflicting report rows; publish their counts.
3. Predefine the textual mapping from machine report lines to PAC present,
   PAC absent/normal wording, ambiguous, or not stated. Blank report lines and
   absence of a PAC phrase are `not stated` unless the complete machine
   reporting convention supports a prespecified negative class. Do not infer
   clinical absence from silence. A human author must review and approve the
   finite phrase dictionary before outcome comparisons; Codex can implement
   deterministic matching and ambiguity tests.
4. Define a patient-level partition or cohort-scope rule before model
   inference. Do not use MIMIC reports to fit weights, tune thresholds,
   choose phrases, select filters, or choose a model. If a separate
   development subset is used to draft phrase mapping, it cannot also be
   reported as untouched concordance evidence.
5. Verify exact and near-duplicate signal overlap against accessible
   development sources and review whether V3F pretraining included MIMIC-IV-ECG
   or overlapping MIMIC signals. If historical source exposure cannot be
   excluded, disclose that and do not claim an independent dataset test.
6. Report coverage and exclusions first: total records, records with linked
   waveforms, readable 12-lead signals, duration/rate eligibility, report
   statement present/ambiguous/not stated, repeated subjects, duplicate
   signals, and model execution failures. Show full denominators and
   comparison-specific coverage.
7. For phrase-present ECGs, report frozen model scores and operating
   decisions descriptively. Do not calculate clinical sensitivity or
   specificity against automated reports. Any binary report concordance
   statistic must be explicitly named machine-report agreement and accompanied
   by the phrase mapping, abstention/not-stated rate, and patient-clustered
   uncertainty.
8. Keep IDs, report text, row-level scores, and waveforms inside restricted
   storage. Release only reviewed aggregate counts, protocol, code, hashes,
   and receipts allowed by the PhysioNet license and institutional policy.

## Human and Automated Responsibilities

The implemented parser preserves all 18 report columns, classifies only with a
versioned mapping carrying corresponding-author approval, and returns no raw
text or identifiers. Its checked-in template is empty and not loadable. Unit
tests use synthetic phrases only and are not evidence about MIMIC terminology.
Codex can implement the version-pinned downloader after quota approval, schema
and hash validation, exact duplicate scan, patient-level joins, inference,
aggregate metrics, confidence intervals, and privacy checks. The corresponding
author must still approve the real phrase-to-PAC mapping, license/attribution
treatment, whether model source exposure is adequately disclosed, and the
wording that limits the result to automated-report concordance. Approval of
this design does not imply approval of those separate decisions.

## Stop Conditions

Stop before waveform download if the per-user quota is unknown, the license
terms are not reviewed, report semantics cannot support a prespecified
concordance endpoint, patient linkage is ambiguous, frozen V3F weights cannot
be loaded with a compatible input contract, or the model's prior MIMIC exposure
would make the intended analysis misleading. A stopped or metadata-only stage
must be reported as such; no zero-result or validation claim may be inferred.

## Metadata-Only Implementation Status (2026-11-09)

The deterministic parser, aggregate-only metadata auditor, and aggregate-only
PAC statement auditor are implemented. The metadata auditor accepts local
copies of `record_list.csv` and `machine_measurements.csv`, checks the required
`subject_id`/`study_id` keys and 18 report slots, counts duplicate keys,
conflicting duplicate report rows, unmatched joins, unique subjects, and
whether any report text is present. It emits input SHA-256 values and aggregate
counts only. Invalid keys, missing report slots, duplicate keys, conflicts, or
unmatched joins prevent a `valid` status.

The PAC statement auditor first requires a mapping that passes
`load_approved_pac_mapping`, then requires a valid exact metadata join before
classifying any report row. It outputs input and mapping hashes, cohort counts,
and counts for explicit positive, explicit negative, uncertain/qualified, and
not-mentioned/report-missing states. The aggregate omits all IDs, paths, report
text, and row-level classifications. Its policy explicitly records that this
is not clinical reference data and that waveform inference and performance
metrics were not performed. The parser fails closed to uncertain when common
unmapped negation or qualifier cues occur near a PAC match, and it does not
match phrases across sentence or semicolon boundaries. These generic safeguards
are not a substitute for author review of the real phrase mapping. Commands:

```text
python scripts/benchmarkmax/audit_mimic_metadata.py --record-list ... --machine-measurements ... --output ...
python scripts/benchmarkmax/audit_mimic_pac_statements.py --record-list ... --machine-measurements ... --mapping ... --output ...
```

Synthetic tests pass for matching metadata, privacy of the output, conflicting
duplicates, unmatched keys, missing report slots, empty join keys, approved
and pending phrase mappings, report-state aggregation, and aborting on an
invalid join. No real MIMIC metadata, report text, or waveform has been
downloaded or processed; the checked-in phrase mapping remains empty and
unapproved.
