## Custodian request boundary

The round-2 export includes a draft, not a sent request. If the authors choose to ask again, request only a catalog/listing for the named artifact categories: backup identifier/date/time/time zone; relative original path; size and custodian-computed hash; exact archived job logs/scripts/manifests and any checkpoint read/write receipt. Ask which backup systems/date ranges were checked. Do not request bulk restoration or transfer of clinical rows. The previously reported September 4 backup result is bounded to that listing; it does not prove the institution has no other archive.

REV3–REV6 is the latest bounded CEDIA export reviewed. A follow-up read-only filename/metadata search on 2026-11-11 found no exact target names in the known V4.5 project root, `BACKUPS`, or `datos_zip`; see [`CEDIA_TARGETED_RECOVERY_SEARCH_2026-11-11.json`](receipts/CEDIA_TARGETED_RECOVERY_SEARCH_2026-11-11.json). This excludes archive contents, other names/roots, the institutional catalog, other accounts, and privileged scheduler spool. Without a new catalog identifier, archive path, or custodian-provided artifact, repeating these same filename searches would not extend the evidence ceiling. REV6 also adds a static copy of the 60/40 Optuna objective source, but no verified link to the May jobs or recovered database bytes.
